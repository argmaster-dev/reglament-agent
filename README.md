# Агент поиска ответов по регламентам

Прототип для задачи «Поиск ответов по корпоративным документам» конкурса «ИИкузница», трек «Аналитик данных».

Сотрудник задаёт вопрос в чате. Агент отвечает коротко, своими словами, со ссылками на пункты регламентов. Если ответ зависит от подразделения или этапа, агент уточняет. Если ответа в регламентах нет, агент создаёт обращение в службу качества. Ответ эксперта пополняет базу знаний, и на повторный вопрос агент отвечает уже по нему.

## Состояние

Идёт спринт 26–28 ноября 2026 года. Доступна первичная загрузка и версионирование регламентов.

## Загрузка регламентов

Понадобятся Python 3.12+, uv, PostgreSQL с расширением pgvector и локальная Ollama с моделью `bge-m3`. Для базы и тестовой почты предусмотрен Compose. При первом запуске создайте пароль базы, сохраните его и при последующих запусках используйте то же значение. При подключении через URL специальные символы пароля требуют percent-encoding.

```bash
export POSTGRES_PASSWORD="$(openssl rand -hex 24)"
docker compose up -d --wait
export DATABASE_URL="postgresql://regulations:${POSTGRES_PASSWORD}@127.0.0.1:${REGULATIONS_DB_PORT:-5432}/regulations"
uv sync --locked
uv run python -m reglament_agent.ingest load docx/
```

Для существующей базы достаточно задать её `DATABASE_URL`. Адрес Ollama по умолчанию — `http://127.0.0.1:11434`, его можно изменить через `MODEL_OLLAMA_URL`. Для сервиса нужны права установки расширения или заранее установленный pgvector. Миграции применяются при запуске загрузки. Векторы вычисляются на CPU.

Команда читает карточки из `docx/documents.toml` и печатает JSON по каждому файлу. При повторе того же файла возвращается номер сохранённой версии. При замене исходник, пункты и переключение активной версии публикуются одной транзакцией. Поиск читает только активные документы и учитывает подразделение и этап.

Тесты запускаются командой `uv run pytest`. По умолчанию они используют временный PostgreSQL из pgserver. Если задан `DATABASE_URL`, тесты создают в этой базе изолированную схему.

## Поиск и источники

Поиск объединяет по позициям три списка кандидатов: близкие векторы, совпадения значимых слов и совпадения фразы. Сокращения раскрываются по глоссарию заказчика. Если подразделение неизвестно, выдача сохраняет места для нескольких подразделений с совпадениями. При известном подразделении или этапе фильтр применяется до ранжирования.

Для маршрута диалога `reglament_agent.storage.retrieve.retrieve` возвращает пункты и отдельный список опубликованных FAQ от подключённого поставщика. Ссылка на пункт хранит номер редакции, номер пункта и, при необходимости, предложение или колонку таблицы. По этой ссылке `reglament_agent.storage.sources.point_view` открывает текст соответствующей редакции.
