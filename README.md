# Агент поиска ответов по регламентам

Прототип для задачи «Поиск ответов по корпоративным документам» конкурса «ИИкузница», трек «Аналитик данных».

Сотрудник задаёт вопрос в чате. Агент отвечает коротко, своими словами, со ссылками на пункты регламентов. Если ответ зависит от подразделения или этапа, агент уточняет. Если ответа в регламентах нет, агент создаёт обращение в службу качества. Ответ эксперта пополняет базу знаний, и на повторный вопрос агент отвечает уже по нему.

## Состояние

Идёт спринт 26–28 ноября 2026 года. Доступна первичная загрузка и версионирование регламентов.

Профиль сотрудника хранит подразделение, должность или роль в процессе и дату подтверждения.
Подразделение в вопросе действует для текущей темы. Чтобы поменять профиль, можно сказать
«Я теперь в Дирекции ИБ» или «Моя должность — логист». Профиль виден и сбрасывается из чата.
`DIALOG_PROFILE_MAX_AGE_DAYS` задаёт порог повторного подтверждения подразделения. По умолчанию
это 30 дней. Одно подтверждение предлагается за диалог при первом вопросе, где нужен профиль.

## Загрузка регламентов

Понадобятся Python 3.12+, uv, PostgreSQL с расширением pgvector и локальная Ollama с моделью `bge-m3`. Для базы и тестовой почты предусмотрен Compose. При первом запуске создайте пароль базы, сохраните его и при последующих запусках используйте то же значение. При подключении через URL специальные символы пароля требуют percent-encoding.

```bash
export POSTGRES_PASSWORD="$(openssl rand -hex 24)"
docker compose up -d --wait
export DATABASE_URL="postgresql://regulations:${POSTGRES_PASSWORD}@127.0.0.1:${REGULATIONS_DB_PORT:-5432}/regulations"
uv sync --locked
uv run python -m reglament_agent.ingest load docx/
```

Для существующей базы достаточно задать её `DATABASE_URL`. Адрес Ollama по умолчанию — `http://127.0.0.1:11434`, его можно изменить через `MODEL_OLLAMA_URL`. Для сервиса нужны права установки расширения или заранее установленный pgvector. Миграции применяются при запуске загрузки. Векторы вычисляются на CPU.

Команда читает карточки из `docx/documents.toml` и печатает JSON по каждому файлу. При повторе того же файла возвращается номер сохранённой версии. При замене исходник, пункты и переключение активной версии публикуются одной транзакцией. Поиск читает только активные документы и учитывает подразделение и этап.

Тесты запускаются командой `uv run pytest`. По умолчанию они используют временный PostgreSQL из pgserver. Если задан `DATABASE_URL`, тесты создают в этой базе изолированную схему.

## Поиск и источники

Поиск объединяет по позициям три списка кандидатов: близкие векторы, совпадения значимых слов и совпадения фразы. Сокращения раскрываются по глоссарию заказчика. Если подразделение неизвестно, выдача сохраняет места для нескольких подразделений с совпадениями. При известном подразделении или этапе фильтр применяется до ранжирования.

Для маршрута диалога `reglament_agent.storage.retrieve.retrieve` возвращает пункты и отдельный список опубликованных FAQ от подключённого поставщика. Ссылка на пункт хранит номер редакции, номер пункта и, при необходимости, предложение или колонку таблицы. По этой ссылке `reglament_agent.storage.sources.point_view` открывает текст соответствующей редакции.

## Запуск стенда

Нужны Docker, Ollama с моделями `qwen3.5:9b-q4_K_M` и `bge-m3`, файл `.env` (образец — `.env.example`).

```bash
cp .env.example .env   # заполните пароли и секрет
docker compose up -d --build --wait
```

Приложение слушает `127.0.0.1:${APP_PORT:-8000}`, Postgres и Mailpit опубликованы только на loopback. Сеть `backend` внутренняя.

**Ollama на хосте.** Контейнер обращается к ней через `host.docker.internal` (`extra_hosts: host-gateway`). Ollama должна слушать адрес, доступный с docker-моста, например `OLLAMA_HOST=0.0.0.0:11434` (при этом закройте порт 11434 файрволом от внешней сети). Альтернатива — запустить приложение на хосте: `make run` (Chainlit, `src/reglament_agent/chat/app.py`, файл появляется вместе с чатом; читает `.env`, `MODEL_OLLAMA_URL=http://127.0.0.1:11434`).

**Сброс демо.** `make demo-reset` стирает всю схему БД, применяет миграции и загружает все регламенты; `make demo-reset-without-td` — без `td-project` (чтобы показать добавление регламента). Команда требует `--yes` или `DEMO_RESET_ALLOWED=1`. Переменные: `EMBEDDER=ollama|fake`, `DEMO_RESET_SCHEMA` (по умолчанию `public`). Выводит JSON: документы, пункты, секунды.

**Проверка состояния.** `GET /health` (роутер `reglament_agent.ops.health.router`, подключается в приложение) возвращает JSON по БД, Ollama и SMTP; 503 только если недоступна БД.

## Запуск (разработка)

```bash
export PATH=$HOME/.local/bin:$PATH
uv sync
uv run chainlit run src/reglament_agent/chat/app.py --headless --port 8000
```

Откройте http://localhost:8000 и выберите роль. При настроенной `DATABASE_URL` чат ищет по активным версиям регламентов и опубликованным ответам службы качества. Кнопка под ответом открывает точное предложение или колонку. При нехватке основания обращение и письмо попадают в очередь одной транзакцией. Для локального предпросмотра интерфейса без БД используются заглушки.

| Переменная | Назначение |
|---|---|
| `CHAT_EXPERT_PASSWORD` | пароль роли «Служба качества»; для разработки по умолчанию `demo-expert` |
| `CHAINLIT_AUTH_SECRET` | секрет подписи сессий; если не задан, создаётся случайный на время процесса |
| `CHAT_TRUSTED_HEADER` | например `X-User-Email`: личность берётся только из этого заголовка. Прокси обязан сам выставлять его и удалять из запросов клиента |
| `CHAT_EXPERT_EMAILS` | список адресов экспертов через запятую (только в режиме доверенного заголовка) |
| `CHAT_SERVICES_FACTORY` | Фабрика сервисов чата. В Compose по умолчанию используется `reglament_agent.dialog.services:build_services` |
